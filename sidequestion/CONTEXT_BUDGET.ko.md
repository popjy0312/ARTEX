# 긴 우회 대화와 컨텍스트 예산

2026-09-11 수정. 기존 구현은 요청 JSON의 문자 수를 그대로 토큰으로 간주하고 주 작업의 32K 출력 예약을 상속했습니다. 그 결과 HTML, JS, 도구 결과가 많으면 정상적인 우회 질문을 너무 일찍 거부했습니다.

## 오픈 소스 구현 대조

- [Grok CLI 우회 컨텍스트](https://github.com/superagent-ai/grok-cli/blob/fb97af83f06dca873281d60168430f06c8de6324/src/agent/agent.ts#L739): 최근 사용자/어시스턴트 텍스트에서 조각을 추출하고 문자 예산은 약 2000, 항목당 최대 400자입니다. 이 경로에서는 연속적인 우회 질문 기록을 유지하지 않습니다.
- [Grok CLI 독립 요청](https://github.com/superagent-ai/grok-cli/blob/fb97af83f06dca873281d60168430f06c8de6324/src/utils/side-question.ts): 독립 취소 신호를 사용하고 모델이 지원하면 출력 한도는 2048 tokens이며 도구를 제공하지 않습니다.
- [Grok CLI 주 세션 압축](https://github.com/superagent-ai/grok-cli/blob/fb97af83f06dca873281d60168430f06c8de6324/src/agent/compaction.ts): 토큰을 추정하고 최근 내용을 보존하며 새 내용을 이전 요약에 반영하고 턴 사이의 잘라내기를 처리합니다.
- [OpenCode 세션 압축](https://github.com/anomalyco/opencode/blob/b3f1a96c6dd7adeb28b36dd11add1998fc84d67b/packages/core/src/session/compaction.ts): 전체 요청을 추정하고 출력/버퍼를 예약하며 최근 내용과 롤링 요약을 유지하고 도구 없는 요약 요청을 사용합니다. 이 구현은 최근 예산 8000, 요약 출력 한도 4096 tokens를 기본으로 합니다.
- [OpenCode 오버플로 복구](https://github.com/anomalyco/opencode/blob/b3f1a96c6dd7adeb28b36dd11add1998fc84d67b/packages/core/src/session/runner/llm.ts): 어시스턴트 출력이 시작되기 전에만 오버플로 복구를 시도하며 복구 후 호출은 같은 복구 경로에 다시 들어가지 않습니다.

ARTEX는 독립 출력 예산, 최근 내용과 롤링 요약, 제한된 복구 방식을 참고합니다. Grok의 텍스트 추출을 그대로 복사하지 않고 norma v0.3.6의 구조화 메시지와 도구 짝을 유지하며, OpenCode 주 세션 압축 이벤트를 ARTEX 주 transcript에 기록하지 않습니다.

## 요청 예산과 실행

- 메시지는 norma의 콘텐츠 블록별 UTF-8 바이트 추정과 4/3 여유를 사용합니다. 시스템 프롬프트, 도구 스키마와 메시지 래퍼 오버헤드도 추가로 계산합니다. 추정치는 모델의 정확한 토큰 수가 아닙니다.
- 우회 출력은 기본적으로 최대 8192 tokens이고 주 설정의 출력 상한도 넘지 않습니다. 서비스 환경 변수 `ARTEX_BTW_MAX_OUTPUT_TOKENS`로 256–32768 범위의 상한을 설정할 수 있으며 제품 기본 모델이나 주 작업 파라미터는 바꾸지 않습니다.
- 입력 예산은 컨텍스트 창에서 출력 상한과 안전 여유를 뺀 값입니다. 창 크기를 알 수 없으면 플랫폼 기본값 200K를 사용합니다. 안전 여유는 창의 5%이며 최소 128, 최대 8192 tokens입니다.
- 성공한 질문/답변은 순번이 증가하는 방식으로 한 번에 최대 20개씩 불러옵니다. 원문은 최대 20개를 보존하고 토큰 예산은 입력 예산의 1/4 이하이면서 16K 이하입니다.
- 예산을 초과한 답변은 롤링 요약으로 합칩니다. 요약에는 과거 출처와 컨텍스트 시각을 포함합니다. 과거 어시스턴트 답변은 새로운 도구 증거와 같지 않으며 충돌 시 최신 주 스냅샷을 우선합니다.
- 주 컨텍스트가 여전히 길면 복사본의 오래된 메시지만 요약하고 최근에는 최대 8K tokens를 보존합니다. 잘라내는 지점은 도구 호출과 결과를 분리하지 않습니다. 너무 큰 한 묶음은 전체가 요약으로 들어갑니다.
- 요약 입력은 실제 남은 창에 맞춰 UTF-8 안전 단위로 나누고 출력 상한은 2048 tokens입니다. 빈 요약, 잘린 요약, 도구 호출이 포함된 요약 또는 요약 예산을 초과한 요약은 캐시에 쓰지 않습니다. 우회 질문 하나는 최대 12회의 요약 호출을 하며 같은 120초 제한을 적용받습니다. 한도에 도달하면 무한 반복하지 않고 명확히 실패합니다.
- 모델이 처음 컨텍스트 초과를 반환했지만 아직 텍스트나 도구 호출이 출력되지 않았다면 더 줄여 최대 한 번 재시도합니다. 추정 크기가 줄지 않으면 즉시 복구를 중지합니다. 다른 모델 오류와 일부 스트리밍 출력은 이 복구를 실행하지 않습니다.
- 요약, 실패 시도와 취소 시 사용량을 포함해 얻은 모든 사용량을 같은 우회 요청에 누적합니다. Provider가 사용량을 반환하지 않으면 0만 기록할 수 있으며 추정치를 실제 사용량처럼 표시하지 않습니다.

## 영속화와 인터페이스

`side_question_sessions.memory`에는 오래된 질문/답변 요약, 포함된 ordinal, 스냅샷 ID별로 캐시한 주 컨텍스트 요약을 저장합니다. `side_question_requests.context_info`에는 준비 단계, 실제로 재생한 묶음 수, 요약 사용 여부와 예산 추정을 저장합니다.

원래 요청이 아직 실행 중이고 정리 버전이 일치할 때만 요약을 저장합니다. 비우기는 캐시도 지우며 늦은 쓰기가 삭제된 데이터를 되살리지 못합니다. 새 스냅샷은 이전 스냅샷 요약을 재사용하지 않습니다. 요약 필드는 v3 작업 보관에 저장하며, 이전 v3를 복구할 때 없는 필드는 빈 객체로 채웁니다. v1/v2도 계속 호환합니다.

POST는 먼저 요청을 접수하고 반환하며 준비와 압축은 승인 잠금이나 데이터베이스 트랜잭션을 점유하지 않고 백그라운드에서 실행합니다. SSE/기록은 준비, 질문 정리, 복사본 압축, 답변 단계를 표시합니다. 압축 실패는 해당 우회 요청의 실패 종단 상태로 저장합니다. 프론트엔드는 오류를 보존하고 실패한 질문의 초안을 복원하며 입력창을 가리는 토스트를 사용하지 않습니다. 기록 폴링은 더 이상 제출 오류를 지우지 않습니다.
